# Project documentation

Each active POC gets one directory named with a stable, lowercase slug, for example `projects/carcare/`. Do not create empty directories for ideas that are still only in the [catalog](../portfolio/project-catalog.md).

Start each new POC in its own Codex session. In that session, read the [catalog](../portfolio/project-catalog.md), the [current workflow](../shared/workflow/workflow.md), and only the relevant project documents. Confirm the selected project's distinct product problem and initial boundary before writing its documents or Base44 prompts.

Start each directory with a `README.md` containing:

- Product name and the problem that makes it distinct in the portfolio
- Current phase and next documented decision
- Links to the current product brief and other key documents
- Code repository, prototype, or demo links when available

Add folders only when needed. Use `docs/product/`, `docs/design/`, `docs/pages/`, `docs/architecture/`, `docs/decisions/`, and `prompts/` as applicable. Keep one canonical file for each current document. Shared methods and rules belong in [`shared/`](../shared/workflow/README.md).
